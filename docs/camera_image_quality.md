# 摄像头拍照模糊：根因分析与解决方案

> 结论先行：**这不是相机坏了，而是代码从来没驱动过这台相机的自动对焦。**
> 项目用的 Pi Camera v3（IMX708）是带音圈马达的**自动对焦**模组，但 `camera.py` 一直是
> `start()` → `sleep(2)` → `capture_file()` —— 等于**盲拍**：对焦环可能停在无穷远，
> 拍 0.5~2m 外的花架必然整幅发虚。已修复，另有 3 项物理层原因需要在现场排除。

---

## 1. 问题定性：系统此前只有「有没有相机」，没有「拍得好不好」

`camera.py` 原有的失败处理做得相当扎实（`not_found` / `unreachable` / `unknown` 分类 + 修复建议 + 拒绝静默降级），但那套机制**只覆盖"相机能不能用"，完全不覆盖"拍出来的图能不能信"**。

后果是最危险的一类静默失败：

```
相机 → 拍出一张糊图 → base64 塞给 Claude → AI 一本正经地输出
"多肉区光照充足，叶片饱满""中生植物叶尖略黄，可能为浇水偏多"
                                    ↑ 这些结论建立在一张连叶片都看不清的图上
```

输出格式正常、评分正常、推送到钉钉也正常 —— 但内容不可信。这与项目「绝不静默失败」的原则直接冲突，所以本次修复不只是调参数，还包括**给画质加上可观测性**。

---

## 2. 根因分诊表

「模糊」在光学上有三种完全不同的成因，**症状指纹不同**，先对号入座再动手，不要瞎调参数。

| 症状指纹 | 根因 | 层级 | 处置 |
|---|---|---|---|
| 整幅均匀发虚，画面里**找不到任何一处清晰** | **S1 自动对焦从未被触发** ← **本次主因** | 软件 | 已修复：拍照前显式跑对焦循环 |
| 每次糊的程度不一样，时好时坏 | S2 只固定 sleep 2s，AE/AWB/AF 未收敛 | 软件 | 已修复：等待对焦状态 + 丢帧稳定 |
| 静止物体边缘尚可，但**叶片有拖影/重影** | S3 暗光下曝光被拉到几十~上百 ms | 软件 | 已修复：限制曝光上限 1/15s |
| 一半清晰一半糊，**分层**明显 | P3 景深不足（光学限制） | 物理 | 见 §6，需改安装或接受 |
| 雾感、高光有光晕，**拍什么都一样糊** | P1 镜头保护膜没撕 | 物理 | 撕膜 |
| 局部模糊斑块 / 亮斑 / 整片雾 | P2 水渍、水雾、灰尘、结露 | 物理 | 擦净（本项目会喷水，高危） |
| 偶发对焦失败 | P4 AF 马达 300mA 峰值拉垮共用电源 | 物理 | 相机单独供电 / 换 27W 电源 |

### 软件层根因明细

| # | 问题 | 证据 |
|---|---|---|
| S1 | AF 从未触发 | 全文件搜索无 `set_controls` / `autofocus_cycle` / `AfMode` / `AfTrigger` |
| S2 | 3A 未收敛 | 仅 `time.sleep(warmup_sec)`，且不读任何 metadata 判断状态 |
| S3 | 曝光无上限 | 未设 `FrameDurationLimits`；IMX708 最长曝光可达 **1.72s**，清晨 7~9 点拍必拖影 |
| S4 | 分辨率非原生 | 请求 1920×1080，但 IMX708 **没有这个模式**（见 §3），ISP 需重采样，画面偏软 |
| S5 | 无画质门禁 | 诊断脚本只判 `size < 20KB`，对"糊"毫无感知 |

## 3. 硬件事实（决定了方案的边界）

| 项目 | 实测/规格值 | 对本次问题的影响 |
|---|---|---|
| 传感器 | Sony **IMX708**，4608×2592，1/2.43″，像素 1.4µm | — |
| **原生 sensor mode** | 只有 **4608×2592** / **2304×1296** / **1536×864** | ⚠️ **1920×1080 不在其中**，需 ISP 重采样 → 已改为 2304×1296 |
| 对焦 | **PDAF + VCM 自动对焦**，合焦约 **10cm~∞** | 必须软件触发，这是主因 |
| 曝光范围 | 26µs ~ **1.72s**，帧时长 69.7ms~1.72s | 暗光下 AEC 会拉满 → 运动模糊 |
| 光圈 | f/1.8 | 景深浅 → §6 的分层模糊 |
| AF 马达电流 | 峰值约 300mA | 与 4 路水泵共用电源时可能被拉低 |

> 补充一个容易踩的坑：**Picamera2 在 `AfMode=Continuous` 下调用 `autofocus_cycle()` 会直接抛 `RuntimeError`。**
> 所以静止的花架场景应该用 `AfMode=Auto`（单次对焦）+ 拍照前显式触发，而不是 continuous。

## 4. 已实施的修复

### 4.1 `hardware/camera.py`

| 变更 | 说明 |
|---|---|
| **拍照前触发自动对焦** | 新增 `_wait_for_focus()`，调用 `autofocus_cycle()` 并记录 `triggered` / `locked` / `elapsed_sec` |
| **丢弃收敛帧** | 新增 `_settle()`，拍照前丢 2 帧让 AE/AWB 进入稳态 |
| **下发拍摄控件** | 新增 `apply_capture_controls()`，逐个下发 `AfMode` / `AfRange` / `FrameDurationLimits` / `AeExposureMode` / `Sharpness` / `NoiseReductionMode`，**某个控件不支持只记录不中断** |
| **限制曝光上限** | `FrameDurationLimits=(1000, 66666)` → 最长 1/15s，抑制水叶拖影 |
| **分辨率原生模式提示** | 新增 `native_mode_hint()`，请求非原生尺寸时明确告警并给出建议值 |
| **带回拍摄元数据** | 改用 `capture_request()` 同帧取 `ExposureTime` / `AnalogueGain` / `LensPosition` / `AfState` —— 出问题时能归因，而不是靠猜 |
| **画质门禁** | 新增 `assess_image()` + `judge_quality()`，成片低于阈值时打 WARNING 并给出处置建议 |

关键设计取舍：

* **对焦失败不阻断拍照。** 拍照是浇水/报告流程的一环，不能被对焦拖死。失败只记 `note` + 打 WARNING。
* **画质门禁只告警不拦截。** 同理由。但结论会一路带到 `status()`、日志、钉钉消息和报告抬头。
* **兼容测试替身。** 所有新能力用 `hasattr` / `try-except` 包裹，仅有 `capture_file()` 的假对象也能跑通。

### 4.2 `config.yaml`

```yaml
camera:
  resolution: [2304, 1296]   # 原 1920x1080 非 IMX708 原生模式，需 ISP 重采样
  autofocus: auto            # 静止花架用单次对焦；原代码根本没设过
  af_range: normal           # 主拍 <30cm 近景时改 macro
  max_exposure_us: 66666     # 1/15s 曝光上限，防拖影
  exposure_mode: auto        # 可改 short 优先短曝光
  sharpness_boost: 1.5
  jpeg_quality: 95
  settle_frames: 2
  quality_guard:
    enabled: true
    min_sharpness: 8.0
    min_contrast: 12.0
```

### 4.3 `assistant.py` / `tools/camera_diag.py` / `tests/photoAndAnalyse.py`

* `assistant.py` 新增 `_quality_banner()`：画质异常时，**告警横幅顶到报告和钉钉消息最前面**，不再让 AI 拿糊图装作一切正常。
* `camera_diag.py` 增加 `--live` 画质体检：输出清晰度/对比度/亮度、对焦过程、拍摄元数据、分诊结论；`--baseline` 可存基线供日后对比；退出码 **2 = 相机可用但画质异常**（便于脚本化）。
* `photoAndAnalyse.py` 拍完直接打印画质指标与建议 —— 这是最直接的现场验证入口。

## 5. 现场验证流程（树莓派上约 5 分钟）

```bash
cd ~/WateringAssistant

# 1) 环境层：确认相机可见、控件是否真的下发成功
.venv/bin/python tools/camera_diag.py

# 2) 真实拍照 + 画质体检（重点看「已生效控件」与「画质结论」）
.venv/bin/python tools/camera_diag.py --live

# 3) 连拍几次看稳定性；指标稳定后再存为基线
.venv/bin/python tools/camera_diag.py --live --baseline

# 4) 走完整链路（拍照 + AI 分析），确认报告抬头没有画质告警
.venv/bin/python tests/photoAndAnalyse.py --photo
```

**看照片，不要只看数字。** 指标只用来排序和对比，肉眼判据更准：

| 打开 `data/diag/` 里的照片看到什么 | 结论 |
|---|---|
| 整幅均匀糊、无一处清晰 | 对焦问题仍存在 → 检查 `camera_diag` 输出的 `last_focus` 与 `af_state` |
| 一半清晰一半糊 | 景深限制 → §6 |
| 雾感、高光光晕 | 撕膜 / 擦镜头 |
| 叶子有拖影 | 曝光仍偏长 → 调小 `max_exposure_us` 或改 `exposure_mode: short` |

如果 `已生效控件` 那行出现 `⚠️ 未生效控件`，把 `skipped` 内容发我 —— 那说明当前 libcamera 版本不接受某个控件名，需要按版本调整。

## 6. 景深问题：这是光学限制，不是 bug

按 `docs/hardware_design.md`，相机装在 **L3 顶端、俯角 30°**，一个画面里同时包含：

* L3 顶层的植物：距相机约 **0.3~0.5m**
* L1 底层的盆栽/储水桶：距相机约 **1.5~2m**

f/1.8 大光圈 + 6 倍的距离跨度 → **景深范围远不足以让两者同时清晰**。这是物理规律，调焦只能二选一：

| 方案 | 效果 | 代价 |
|---|---|---|
| A. 对焦锁定在中距离（**推荐先试**） | `lens_position` 设 0.8~1.2 屈光度，全画面平均最清楚 | 两端都轻微软化，但"整体可看" |
| B. 缩小光圈 | 景深变大 | IMX708 光圈固定 f/1.8，**不可调** —— 此路不通 |
| C. 相机后移 / 抬高，拉平视角 | 各层距离差变小 | 需要重新做支架 |
| D. 分区拍两张 | 近景远景各一张，分别对焦 | AI 分析要跑两次，报告要合并 |
| E. 接受现状 | 只保证主要观察区清晰 | 需接受边缘层模糊 |

**建议先试 A。** 具体做法：先把 `autofocus` 设为 `auto` 让相机自动对一次，然后用 `--verbose` 看 `lens_position` 落在多少，再改成 `manual` 钉死在这个值 —— 这样每次拍照都是确定的焦点，不会因为某次对焦"跑偏"而整批照片报废。

## 7. 关于清晰度阈值

`sharpness` 的定义是「原图 − 1.2px 高斯模糊」残差的方差，即**高频能量**，越大越锐。本地标定结果：

| 状态 | sharpness |
|---|---|
| 清晰（基准） | **100.1** |
| 模糊半径 0.6px | 78.1 |
| 模糊半径 1.0px | 53.2 |
| 模糊半径 1.6px | 28.2 |
| 模糊半径 2.4px | 11.3 |
| 模糊半径 4.0px | 1.8 |
| 全糊（纯色） | 0.0 |

默认门槛定为 **8.0**（`bad` 线为 4.8）。这个值取得偏保守 —— **宁可漏报也不误报**，因为对着白墙或纯色背景拍，再清晰的照片指标也很低。

⚠️ **绝对值与拍摄内容强相关**，上述数字来自合成图，只能给量级参考。**请务必在树莓派上拍一张你认可的照片，用 `--live --baseline` 存为基线**，之后用「与基线对比」来判断劣化，比为绝对阈值可靠得多。
